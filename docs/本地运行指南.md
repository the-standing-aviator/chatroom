# 本地运行与功能验收指南

从零把 communicate 跑起来，并逐项验收所有功能。**本文每一步都在本机实测过**，
命令可直接复制。遇到问题看最后的「常见问题」。

---

## 0. 前置检查

只需要 **Docker Desktop**（Windows 上装好后需在设置里启用 WSL 集成）。

```bash
docker version --format '{{.Server.Version}}'
```

能打印出版本号（如 `29.6.2`）就绪。如果报 `failed to connect to the docker API`，
说明 Docker Desktop 没启动，先打开它。

> 如果这条命令在 WSL 里报 `docker: command not found`，去 Docker Desktop →
> Settings → Resources → WSL Integration，把 Ubuntu-24.04 的开关打开。

## 1. 一键起整套（首次约 3~5 分钟）

```bash
cd ~/go-projects/communicate
docker compose up -d --build
```

首次构建要从 `proxy.golang.org` 拉依赖。**如果报 `unexpected EOF`，直接重试同一条命令**
（网络抖动，已实测可恢复）。

等约 10 秒，确认全部起来了：

```bash
docker compose ps
```

期望看到 7 个容器，`postgres` 和 `redis` 显示 `(healthy)`。

再看 gateway 日志确认无报错：

```bash
docker logs communicate-gateway 2>&1 | tail -5
```

期望最后三行是 `websocket server started` / `metrics server started` / `gateway started`，
**没有任何 `level":"fatal"`**。

## 2. 浏览器验收（主路径，最直观）

打开 **http://localhost:8890**

### 2.1 注册与登录

1. 输入昵称 `alice`、密码 `pw123456`，点登录
2. 看到系统提示「注册成功，欢迎 alice」—— 新昵称会自动注册

**再开一个浏览器无痕窗口**（或另一个浏览器）打开同一地址，用 `bob` 登录。
两个窗口并排，就能看到双向效果。

### 2.2 公聊

- alice 输入框发「你好」，**bob 的窗口应立刻收到**
- 顶栏能看到自己的昵称

### 2.3 在线列表

- 右侧栏应列出 `alice` 和 `bob`
- **点在线列表里的人 → 进入私聊**；点「公聊」按钮可切回

### 2.4 私聊

- alice 点 bob 进入私聊，发「悄悄话」
- **只有 bob 收到**，第三方窗口（可再开一个 `carol`）看不到
- bob 那边能看到 alice 发来的私聊，可直接回

### 2.5 历史消息

- **刷新页面**（或关掉重开），重新登录
- 之前的公聊消息会自动拉回来 —— 新来的人能看到刚才聊了什么

### 2.6 改名

- 点顶栏昵称 → 改名成 `alice2`
- 在线列表立刻更新
- **刷新页面后仍是 `alice2`**（改名后重签了 token，免密重连保持新名）

### 2.7 文件上传

- 点输入框左边的回形针 / 文件按钮，选一个本地文件
- 消息区出现文件消息，**带文件名和大小**
- 另一个窗口点下载链接，能取回文件

> 限制：单次上传**请求体**上限 10 MiB。传超过会看到
> 「上传失败（413）：文件过大：请求体上限 10 MiB」。
> 注意 multipart 有几百字节开销，所以**正好 10 MiB 的文件也会被拒**，
> 实际能传的上限是略小于 10 MiB。

### 2.8 心跳保活

不用手动测：页面每 20 秒自动发心跳，闲置几分钟连接不会断。

### 2.9 免密重连

- 刷新页面，**不用重新输密码**就回到登录态（token 存在 localStorage）
- 想验证真正重新登录：浏览器控制台执行 `localStorage.clear()` 后刷新

## 3. 终端客户端（TCP，验证跨传输）

浏览器走 WebSocket，终端客户端走裸 TCP —— 两者共用同一套业务逻辑，可以互通。

**在 WSL 里执行**（Windows 侧的 Go 编不了 WSL 文件）：

```bash
cd ~/go-projects/communicate
/usr/local/go/bin/go build -o /tmp/chat-client ./cmd/client
```

**开两个终端窗口**，分别运行：

```bash
/tmp/chat-client -addr 127.0.0.1:8888
```

启动后会先提示 `昵称:` 和 `密码:` —— 输入后回车（新昵称自动注册）。
两个窗口分别用 `tom` / `jerry` 登录，然后：

- 在 tom 里按 `1` 发公聊 → jerry 窗口收到
- **在浏览器里发消息 → tom/jerry 都能收到**（跨传输互通，这是关键验证）
- 在浏览器在线列表里能看到 `tom` 和 `jerry`

客户端是**菜单式**交互，每轮循环打印菜单，输入数字选择：

| 输入 | 作用 |
|------|------|
| `1` | 公聊（回车后再输入消息内容） |
| `2` | 私聊（先输入对方昵称，再输入内容） |
| `3` | 改昵称 |
| `4` | 在线列表 |
| `5` | 历史消息 |
| `0` | 退出 |

## 4. 压测（验证性能与背压）

```bash
cd ~/go-projects/communicate
/usr/local/go/bin/go build -o /tmp/chat-bench ./cmd/bench

# 100 个客户端，各发 5 条广播
/tmp/chat-bench -addr 127.0.0.1:8888 -n 100 -msg 5 -settle 2s
```

**本机实测输出**：

```
登录: 成功 100/100，耗时 568ms（176.2 个/秒）
广播: 发送 5 条，期望接收 500，实际 500，丢 0
延迟: 平均 2.573ms，P50 2.593ms，P99 2.863ms（样本 500）
```

关键看两点：**「丢 0」**（背压正确）和**延迟**（localhost 应在个位数毫秒）。

想加压力就调大 `-n`，比如 `-n 1000`。

## 5. 监控验收

| 地址 | 账号 | 用途 |
|------|------|------|
| http://localhost:3000 | `admin` / `admin` | Grafana 大盘 |
| http://localhost:9090 | 无 | Prometheus 查询 |
| http://localhost:9093 | 无 | Alertmanager |

### 5.1 Grafana 大盘

打开 http://localhost:3000 → 登录 → 左侧 **Dashboards** → **Communicate 聊天室**

三个面板：在线人数 / 丢消息速率 / goroutine 数。**先在浏览器开几个页面登录**，
在线人数应该涨上去。

### 5.2 Prometheus 抓取正常

浏览器打开 http://localhost:9090/targets —— `communicate` 这个 target 的 State 应为 **UP**。

### 5.3 告警规则已加载

打开 http://localhost:9090/alerts —— 应看到三条规则（当前都应是绿色 inactive）：

- `GatewayDown` — 抓不到 gateway
- `MessagesDropped` — 背压丢消息
- `GoroutineLeak` — 协程泄漏

### 5.4 实测告警（可选，验证闭环）

把 gateway 停掉，等约 1~2 分钟：

```bash
docker compose stop gateway
```

打开 http://localhost:9090/alerts，`GatewayDown` 应变红（pending → firing）。
再起回来：

```bash
docker compose start gateway
```

## 6. 多节点与负载均衡（进阶，验证 V3 分布式）

`docker compose` 的 gateway 有固定 `container_name`，**不能直接 `--scale`**。
要验证多节点，用 `docker run` 起第二个实例（共用同一套 PG/Redis/NATS）：

```bash
docker run -d --name communicate-gateway-2 --network communicate_default \
  -p 8889:8889 -p 8891:8891 \
  -e COMMUNICATE_DSN='postgres://chat:chat@postgres:5432/chat?sslmode=disable' \
  -e COMMUNICATE_JWT_SECRET='dev-secret-change-me' \
  communicate-gateway:local \
  -addr :8889 -ws-addr :8891 -metrics :9101 -node node2 \
  -store postgres -presence redis -redis-addr redis:6379 \
  -bus nats -nats-url nats://nats:4222
```

现在两个节点：node1 在 8888，node2 在 8889。

**验证跨节点互通**：两个终端客户端分别连不同节点

```bash
/tmp/chat-client -addr 127.0.0.1:8888    # 终端 A，登录 alice
/tmp/chat-client -addr 127.0.0.1:8889    # 终端 B，登录 bob
```

实测应看到：
- 在线列表**互相可见**（Redis 共享状态）
- 公聊/私聊**跨节点送达**（NATS 转发）
- 历史消息**两边一致**（同一个 PG）

**验证 LB**：

```bash
cd ~/go-projects/communicate
/usr/local/go/bin/go build -o /tmp/chat-lb ./cmd/lb

# 起 LB，把连接轮流分给两个节点
/tmp/chat-lb -listen 127.0.0.1:9000 -backends 127.0.0.1:8888,127.0.0.1:8889 &

# 压测连 LB
/tmp/chat-bench -addr 127.0.0.1:9000 -n 100 -msg 5 -settle 2s
```

实测输出（100 客户端经 LB 分发到 2 节点）：

```
登录: 成功 100/100，耗时 461ms（217.0 个/秒）
广播: 发送 5 条，期望接收 500，实际 500，丢 0
```

**清理**：

```bash
docker rm -f communicate-gateway-2
```

## 8. 数据持久化验证（重要）

上传的文件存在 Docker 具名卷里，容器重建不会丢。实测验证：

```bash
# 1. 在浏览器上传一个文件，记下下载链接里的 file_id

# 2. 完全销毁并重建容器
docker compose down
docker compose up -d

# 3. 等 gateway 起来后，用刚才的链接下载
#    文件应能正常下载 —— 证明卷挂载生效
```

如果想彻底清空数据重来：

```bash
docker compose down -v   # -v 会删掉所有数据卷（PG 数据 + 上传的文件）
```

## 常见问题

**构建时 `go mod download` 报 `unexpected EOF`**
网络抖动，重试 `docker compose up -d --build`。已实测重试可成功。

**容器起来了但 `docker compose ps` 里 gateway 一直在 Restarting**
看日志 `docker logs communicate-gateway`。如果看到 `init file storage failed`，
说明文件存储目录权限有问题 —— 检查镜像是否是最新的（`--build` 重新构建）。

**浏览器打开 8890 是空白页**
先确认 `curl http://localhost:8890/` 有 HTML 返回。若正常则是浏览器缓存，
强制刷新（Ctrl+Shift+R）。

**WebSocket 连不上（页面一直显示未连接）**
检查 gateway 日志有无 `websocket server failed`。也确认没有别的程序占用 8890 端口。

**端口冲突（8888/8890/3000/9090/9093 被占）**
改 `docker-compose.yml` 里对应服务的 `ports` 映射，比如 `"18890:8890"`。

**`go` 命令找不到**
必须用完整路径 `/usr/local/go/bin/go`，且在 WSL 里执行。Windows 侧的 Go
访问不了 WSL 文件系统。

**Grafana 登录 `admin/admin` 进不去**
这是 compose 里设定的默认密码。若之前改过，用 `docker compose down -v` 重置
（注意会清空所有数据）。
