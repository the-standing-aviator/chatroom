# 需求文档 — 多人实时聊天室（V1）

> 版本：v0.1（2026-10-27）
> 状态：V1 范围已确认
> 关联：里程碑规划见《项目要点记录.md》；已知问题见《问题与解决方案.md》

## 1. 背景与目标

一个真实可用的多人实时聊天室。多客户端通过 TCP 连接同一服务器，登录后实时收发文字消息。

- 练习重点：Go 后端、网络编程、并发。
- 北极星目标：百万级在线（V3 演进方向）。
- 本文件锁定 **V1（正确性）** 范围：把单机版本做对、做扎实、可测试。

## 2. 目标用户与使用场景

- **用户**：通过命令行接入聊天室、与他人实时文字交流的人。
- **运维/开发者**：希望系统可排查、可测试、可部署的人。

核心场景：
1. 用户启动客户端，连接服务器，登录（鉴权）。
2. 用户发送消息，广播给所有在线用户（公聊）。
3. 用户私聊指定在线用户。
4. 用户修改自己的昵称。
5. 用户查看当前在线列表。
6. 用户查看历史消息（持久化后重启不丢）。

## 3. 用户故事

- 作为用户，我要先登录，防止别人冒充我的昵称。
- 作为用户，我发的每条消息要带时间戳，方便看时间线。
- 作为用户，我或别人掉线时，服务器要及时广播"已下线"。
- 作为用户，重启服务器后历史消息不丢失。
- 作为开发者，我要有结构化日志和测试，出问题能快速定位。

## 4. 功能需求（V1，全部 Must）

| 编号 | 功能 | 说明 |
|------|------|------|
| FR-1 | 公聊广播 | 登录用户发的普通消息，广播给所有在线用户 |
| FR-2 | 私聊 | 指定昵称发送，仅对方可见 |
| FR-3 | 改昵称 | 修改自己的昵称，重名需提示且不覆盖 |
| FR-4 | 在线列表 | 查看所有在线用户 |
| FR-5 | 鉴权登录 | 昵称 + 密码（或 Token）；连接后须登录才能发言；防冒充 |
| FR-6 | 消息时间戳 | 每条消息带服务端时间戳 |
| FR-7 | 心跳/断线检测 | 客户端定期心跳，服务端超时判定离线并广播 |
| FR-8 | 消息持久化 | 消息历史落盘（SQLite 起步），支持查看历史 |
| FR-9 | 结构化日志 | 用 zap 记录关键事件，替换 fmt.Println |
| FR-10 | 自动化测试 | 单元测试 + race 检测 + 集成测试 |

## 5. 非功能需求

- **性能**：单机 V1 目标稳定支撑 ≥ 1000 在线；局域网广播延迟 < 100ms。（为 V2 压测留基线）
- **可靠性**：单连接 panic 不崩进程（recover 兜底）；重启后消息历史不丢。
- **安全**：密码不明文存储（bcrypt）；鉴权防冒充；消息明文传输 V1 可接受（TLS 后置）。
- **可观测**：结构化日志覆盖上下线、改名、鉴权、广播等关键事件。
- **可维护**：代码分层清晰、可测试；关键并发逻辑用 race 检测验证。

## 6. 范围外（V1 明确不做）

- TLS/加密传输
- Web/图形界面
- 图片/文件传输
- 多房间/群组
- 分布式/多节点（V3）
- WebSocket（V1 用自定义 TCP）
- 离线消息推送（端外）

## 7. 验收标准

- `go test -race ./...` 通过，无数据竞态。
- 每个功能需求有对应测试用例。
- 手工验收：两个客户端可登录、公聊、私聊、改名、查看在线列表、查看历史。
- 恶意输入（如 `to|张三` 缺字段）不导致进程崩溃。
- 客户端 `-ip`/`-port` 参数生效。
- 5 个已知 bug（见《问题与解决方案.md》P1-1~P1-5）全部修复并标记 🟢。
