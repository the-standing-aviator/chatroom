# 项目要点记录

> 用途：记录本项目从需求到上线复盘的完整流程中的要点、决策与计划，方便随时回头复查。
> 维护方式：每完成一次关键对话/决策，就追加一条到「决策记录」，并同步更新「当前状态」和「下一步」。

## 1. 项目定位

一个**真实可用**的 Go 后端 + 网络编程项目，目标是走通完整项目流程（需求 → 设计 → 开发 → 测试 → 上线 → 复盘），最终成为一个**可面试展示**的项目。

## 2. 目标与约束（2026-10-27 确认）

- **真实可用**：不是教学 demo，是真能多人跑起来的东西。
- **北极星目标**：百万级在线（作为演进方向的北极星，不一步到位）。
- **功能范围**：尽可能丰富，但按优先级分批做透（见里程碑规划）。
- **练习重点**：Go 后端、网络编程、并发。
- **最终目的**：可面试项目 —— 能讲清完整流程 + 技术栈 + 系统设计演进故事。

## 4. 里程碑规划（把"百万在线"拆成三步）

- **V1 正确性**：修对现有单机代码、补测试、补鉴权/持久化/时间戳等基础功能 —— 证明「并发安全 + 协议 + 测试」。
- **V2 性能**：压测找瓶颈，优化连接模型/内存/协程泄漏 —— 证明「性能调优 + Go 运行时」。
- **V3 规模（分布式）**：多节点 + 消息中间件 + 网关 + 分片 —— 证明「系统设计」。

## 5. 目标技术栈（终点形态，逐步引入）

- 核心：Go、goroutine/channel/context、自定义 TCP 协议（后续可加 WebSocket）
- 存储：PostgreSQL（持久化）+ Redis（在线状态/会话/Pub-Sub）
- 消息：NATS 或 Kafka（广播解耦，V3 引入）
- 接口：gRPC / REST（管理、鉴权）
- 鉴权：JWT
- 部署：Docker + docker-compose（本地；K8s 可选）
- 可观测：zap（结构化日志）+ Prometheus（指标）+ pprof（性能分析）
- 测试：单元测试 + race 检测 + 压测
- CI：GitHub Actions
