# 项目要点记录

> 用途：记录本项目从需求到上线复盘的完整流程中的要点、决策与计划，方便随时回头复查。
> 维护方式：每完成一次关键对话/决策，就追加一条到「决策记录」，并同步更新「当前状态」和「下一步」。

## 1. 项目定位

一个**真实可用**的 Go 后端 + 网络编程项目，目标是走通完整项目流程（需求 → 设计 → 开发 → 测试 → 上线 → 复盘），最终成为一个**可面试展示**的项目。

## 2. 目标与约束（2026-10-27 确认）

- **真实可用**：不是教学 demo，是真能多人跑起来的东西。
- **北极星目标**：百万级在线（作为演进方向的北极星，不一步到位）。
- **功能范围**：尽可能丰富，但按优先级分批做透（见里程碑规划）。
- **练习重点**：Go 后端、网络编程、并发。
- **最终目的**：可面试项目 —— 能讲清完整流程 + 技术栈 + 系统设计演进故事。

## 3. 完整流程路线图（6 阶段）

## 4. 里程碑规划（把"百万在线"拆成三步）

- **V1 正确性**：修对现有单机代码、补测试、补鉴权/持久化/时间戳等基础功能 —— 证明「并发安全 + 协议 + 测试」。
- **V2 性能**：压测找瓶颈，优化连接模型/内存/协程泄漏 —— 证明「性能调优 + Go 运行时」。
- **V3 规模（分布式）**：多节点 + 消息中间件 + 网关 + 分片 —— 证明「系统设计」。

## 5. 目标技术栈（终点形态，逐步引入）

- 核心：Go、goroutine/channel/context、自定义 TCP 协议（后续可加 WebSocket）
- 存储：PostgreSQL（持久化）+ Redis（在线状态/会话/Pub-Sub）
- 消息：NATS 或 Kafka（广播解耦，V3 引入）
- 接口：gRPC / REST（管理、鉴权）
- 鉴权：JWT
- 部署：Docker + docker-compose（本地；K8s 可选）
- 可观测：zap（结构化日志）+ Prometheus（指标）+ pprof（性能分析）
- 测试：单元测试 + race 检测 + 压测
- CI：GitHub Actions

- **2026-10-30（V2 性能第一仗）**
  - 新增压测客户端 `cmd/bench`，复用 `internal/protocol` 帧编解码，测在线数/广播延迟/丢消息。
  - 压测发现广播延迟 P50 ~19ms（localhost 应亚毫秒），打点定位到广播路径上的同步 SQLite 写（`save_db` ~25ms）。
  - 验证并推翻 Nagle 假设（加 `SetNoDelay` 无收益，回退）。
  - 异步持久化：`saveCh` + `saveLoop` 后台落盘，广播延迟降到 ~0.9ms（约 20 倍）。
  - 优雅关闭：`Shutdown` 三段式（停生产者 → 关队列 → 消费者排空），正常关闭 flush 不丢消息。
  - 产出 P2-1 记录（见《问题与解决方案.md》）。

- **2026-10-30（规模基线）**
  - 跑通 `-n 1000` 基线：登录 1000/1000，广播 1000 连接端到端延迟约 2.8ms（settle 后）。
  - 打点二分定位「延迟虚高」：服务端扇出仅 2.8ms，端到端 118ms 是 bench 自身 200ms 读超时 artifact。
  - 修复 bench receive（去 200ms 空转改一直阻塞读）+ 新增 `-settle` 参数，测纯广播延迟。
  - 发现真实隐患：登录上下线广播积压挤占 sendCh，归入背压阶段处理。

- **2026-10-30（背压）**

- **2026-10-31（V3.1 存储迁移）**

- **2026-11-02（V3.2 状态外置 + JWT）**
  - 新增 `internal/presence`：`Presence` 接口（Join/Leave/Rename/Online/Node）+ 内存实现 + Redis 实现（单个哈希 `name→node`，Rename 用 Lua 脚本保证「查旧名 + 查新名 + 搬移」原子）。
  - 新增 `internal/auth`：JWT 签发/校验（HMAC-SHA256 对称签名），`Issue` 写 sub 声明，`Verify` 区分 `ErrInvalid`/`ErrExpired`。
  - 服务端接线（ports & adapters）：`NewServer` 注入 `presence.Presence` + `auth.Manager`；`addSession`/`removeSession`/`rename`/`who` 改走 presence——昵称全局唯一、在线列表跨节点视角；登录/注册成功后签发 JWT，`auth_token` 帧走免密重连（以 token 的 sub 定身份、成功后 re-issue 实现滑动过期）。
  - `main.go` 加 `-presence memory|redis` / `-redis-addr` / `-jwt-secret` / `-jwt-ttl`，默认 memory 向后兼容。
  - 测试：presence 契约测试（同一套用例跑 Memory + Redis，Redis 不可用则 skip）、auth 5 用例（往返/篡改/错密钥/过期/垃圾）、server 新增 auth_token 重连 2 用例（有效 token 上线 + 非法/过期拒绝）。
  - 边界说明：presence 只提供「全局唯一 + 全局在线列表」视角，消息投递仍走本地 `sessions map`；跨节点私聊/公聊留 V3.3（NATS + 拆接入层）。
